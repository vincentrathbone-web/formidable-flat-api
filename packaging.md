# Packaging Guide — Formidable Flat API

This document contains the complete release packaging process, versioning rules, and troubleshooting for the Formidable Flat API plugin.

---

## Overview

Every code change must be packaged into a versioned ZIP file named `formidable-flat-api-vX.Y.Z.zip`. The ZIP must install cleanly in WordPress via **Plugins → Add New → Upload Plugin**, overwriting the existing `formidable-flat-api/` folder.

> **Release history is permanent.** Previous versioned ZIPs (e.g. `formidable-flat-api-v2.9.0.zip`) must **never** be deleted, renamed, or overwritten when packaging a new build. Each version's ZIP is a historical artifact and part of the release trail. The `package.ps1` script enforces this by **aborting** if a ZIP for the current version already exists — the correct response is always to bump the version, not to remove the existing file.

---

## Version Numbering

The plugin follows **semantic versioning** (MAJOR.MINOR.PATCH):

| Segment | When to bump | Example |
|---------|-------------|---------|
| **MAJOR** | Breaking API changes, architecture overhaul | 3.0.0 |
| **MINOR** | New features, shortcode params, UI changes | 2.6.0 |
| **PATCH** | Bug fixes, style tweaks, packaging fixes | 2.6.7 |

### Files to Update When Bumping Version

All three must match. If any is out of sync, users get stale cached assets or confusing version displays.

| File | Location | Example |
|------|----------|---------|
| Plugin header | `formidable-flat-api.php` line 6 | `Version: 2.10.4` |
| Version constant | `formidable-flat-api.php` line 12 | `define( 'FRM_FLAT_VERSION', '2.10.4' );` |
| Package script | `package.ps1` `$version` variable | `$version = "2.10.4"` |
| User documentation | `PLUGIN.md` **Version:** field at top | `**Version:** 2.10.4` |
| ZIP filename | Generated by `package.ps1` | `formidable-flat-api-v2.10.4.zip` |

> **Rule:** Always update the plugin header `Version:` and `FRM_FLAT_VERSION` constant **together**. The ZIP filename is derived from the version in `package.ps1`.

## The Packaging Script

**File:** `package.ps1` (PowerShell, located in the plugin root)

### What It Does

1. Reads the version number from its own `$version` variable.
2. Creates a temporary `formidable-flat-api/` folder in `%TEMP%`.
3. Copies all project files into that folder, excluding distribution-irrelevant items (including any existing `*.zip` — old release ZIPs are **never** bundled inside a new one).
4. **Aborts if a ZIP for the current version already exists** in the plugin root. This protects prior release artifacts from being silently overwritten. Bump the version and re-run.
5. Uses **Python's `zipfile` module** to create the ZIP with forward slashes.
6. Verifies the ZIP structure using .NET's `System.IO.Compression.ZipFile`.
7. Cleans up the temporary folder.

### How to Run

```powershell
powershell -ExecutionPolicy Bypass -File "package.ps1"
```

Or from within the plugin directory:

```powershell
.\package.ps1
```

### Exclusion List

These items are **never** included in the distribution ZIP:

| Pattern | Reason |
|---------|--------|
| `*.zip` | Old packages — prevents nesting |
| `*.md` | Internal documentation and implementation detail — not required at runtime |
| `.claude/` | AI config — not user-facing |
| `.qwen/` | AI config — not user-facing |
| `package.ps1` | Build script — not needed at runtime |
| `gemini.md` | Dev context — not user-facing |
| `CLAUDE.md` | Dev context — not user-facing |
| `chat.log` | Dev history — not user-facing |
| `inspect_views.php` | Debug script — not user-facing |
| `.git/` | Version control — not user-facing |
| `.gitignore` | Version control — not user-facing |

## ZIP Structure Requirements

### Must Have

```
formidable-flat-api-v2.10.4.zip
└── formidable-flat-api/
    ├── formidable-flat-api.php
    ├── class-flat-api-admin.php
    ├── class-flat-api-engine.php
    ├── class-flat-api-rest.php
    ├── class-xlsx-writer.php
    └── assets/
        ├── frontend.css
        ├── frontend.js
        ├── table.css
        └── table.js
```

### Rules

| Rule | Detail |
|------|--------|
| **Single root folder** | Only `formidable-flat-api/` at the ZIP root |
| **Forward slashes** | All paths must use `/` (ZIP standard), never `\` |
| **No stray files** | Only the files needed for runtime |
| **Matching folder name** | The root folder name must be exactly `formidable-flat-api` (not versioned) |

---

## Why Python's zipfile?

PowerShell's `Compress-Archive` on Windows stores paths with **backslashes** (`\`). WordPress's plugin installer expects the ZIP-standard **forward slashes** (`/`) and will fail to parse the folder structure correctly.

### Failed Approaches

| Method | Problem |
|--------|---------|
| `Compress-Archive` | Stores `\` in paths → WordPress can't parse folder structure |
| Binary `\` → `/` replacement | Corrupts ZIP by replacing backslashes inside file content too |
| `Shell.Application` | Unreliable on Windows, encoding issues, timing problems |

### Working Approach

**Python's `zipfile`** always writes forward slashes regardless of the host OS. The `package.ps1` script generates a Python script inline, runs it, and cleans up:

```python
import os, zipfile

with zipfile.ZipFile(zip_path, 'w', zipfile.ZIP_DEFLATED) as zf:
    for root, dirs, files in os.walk(plugin_dir):
        for f in files:
            full = os.path.join(root, f)
            rel = os.path.relpath(full, plugin_dir)
            arcname = plugin_slug + '/' + rel.replace(os.sep, '/')
            zf.write(full, arcname)
```

## Verification After Packaging

After running `package.ps1`, the script automatically verifies:

1. **Single root folder** named `formidable-flat-api`
2. **All entries** are under that folder
3. **Output:** `[PASS] Correct: single 'formidable-flat-api' folder at root.`

For manual verification, open the ZIP in any archive viewer and confirm:
- Only one item at the root: `formidable-flat-api` (folder)
- No files like `formidable-flat-api.php` at the root level

## WordPress Installation Test

After packaging, test the ZIP:

1. Go to **WordPress Admin → Plugins → Add New → Upload Plugin**
2. Upload `formidable-flat-api-vX.Y.Z.zip`
3. Expected: Plugin installs and activates without errors
4. Expected: The existing `wp-content/plugins/formidable-flat-api/` folder is overwritten

### Common Errors

| Error | Cause | Fix |
|-------|-------|-----|
| "No valid plugins were found" | ZIP paths use backslashes (`\`) | Use Python's `zipfile` (already fixed in `package.ps1`) |
| Installs to `formidable-flat-api-v2.6.7/` | WordPress can't parse folder structure, falls back to ZIP filename | Same as above — forward slashes required |
| Plugin folder has nested `formidable-flat-api/formidable-flat-api/` | ZIP has two levels of the same folder name | Ensure `package.ps1` copies files into a single `formidable-flat-api/` folder, not into a folder that already contains one |

## Post-Packaging Checklist

After running `package.ps1`, confirm:

- [ ] Script outputs `[PASS]` for structure verification
- [ ] ZIP filename matches current plugin version
- [ ] Plugin header `Version:` and `FRM_FLAT_VERSION` constant were updated **before** packaging
- [ ] `PLUGIN.md` changelog was updated with the new version entry
- [ ] `HANDOVER.md` and the implementation plan record the completed release
- [ ] ZIP installs cleanly in WordPress (manual test)
- [ ] No old `.zip` files are inside the new ZIP
- [ ] **All previous versioned ZIPs still present** in the plugin root (release history intact)

## Troubleshooting

### "No valid plugins were found"

**Cause:** ZIP paths use backslashes instead of forward slashes.
**Fix:** Ensure `package.ps1` uses Python's `zipfile` (current implementation). Never use `Compress-Archive` directly for distribution builds.

### Plugin installs to wrong folder name

**Cause:** WordPress couldn't determine a consistent single-folder structure from the ZIP.
**Fix:** Ensure the ZIP contains exactly one folder at the root named `formidable-flat-api/` with forward slashes.

### Corrupted ZIP after packaging

**Cause:** Binary manipulation of ZIP files (e.g., replacing `\` with `/`) corrupts file content.
**Fix:** Never modify ZIP bytes directly. Use a proper ZIP library (Python `zipfile`, .NET `ZipFile`, etc.).

### Stale CSS/JS after update

**Cause:** `FRM_FLAT_VERSION` constant not updated, so browser serves cached assets.
**Fix:** Always update `FRM_FLAT_VERSION` alongside the plugin header version. The constant is used in all `wp_enqueue_style` and `wp_enqueue_script` calls.
